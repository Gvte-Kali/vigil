# Développement et contribution

Ces références décrivent l'architecture, les contrats et la migration de Vigil. Elles s'adressent aux contributeurs ; elles ne constituent pas une confirmation de disponibilité de chaque fonctionnalité dans `main`.

## Démarrer

1. Lire [l'architecture cible](architecture-v2.md) et la [portabilité Linux](linux-portability.md).
2. Examiner la [matrice de compatibilité](compatibility-matrix.md) et la [baseline](test-baseline.md).
3. Suivre la [recette native](native-recette.md) avec données synthétiques.
4. Consulter le [Device Manager](device-manager.md), la [sécurité](permissions-audit.md) et la [reprise après incident](session-recovery.md).

## Documents historiques

[L'audit phase 00](phase-00-audit.md) et le [cahier des charges UI](cahier-des-charges-interface.md) sont des documents de conception volumineux. Les décisions ultérieures peuvent les avoir modifiés ; confrontez-les au code avant de les appliquer.

Les contributions sont proposées sur [GitHub](https://github.com/Gvte-Kali/vigil). Ne testez les opérations privilégiées que sur des machines et supports autorisés.
